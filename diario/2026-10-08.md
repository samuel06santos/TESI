### Atividade: Servidor MCP para a aplicação da AP1
- **Pergunta do experimento**: Qual filial do Estilo Marcado oferece um serviço de corte e qual é o preço desse serviço?

---

Nesta atividade, criamos em `aula06/` um servidor MCP local com FastMCP para operar a aplicação Estilo Marcado por sua API HTTP. O servidor oferece quatro tools, com descrições de quando usar cada uma: `listar_filiais`, `listar_servicos` e `consultar_horarios` para leitura; `criar_agendamento` para escrita. O arquivo `aula06/.mcp.json` configura a conexão por `stdio`. Para usá-lo no Claude Code a partir da raiz do TESI, é preciso passar `--mcp-config aula06/.mcp.json`; `.claude/settings.json` define `allow` para as leituras e `ask` para a escrita.

No ensaio com Ollama, pedimos: **“Encontre uma filial com serviço de corte e confirme o nome e o preço de um serviço de corte nessa filial. Não faça reserva.”** O script `aula06/consultar_com_ollama.py` apresentou ao modelo apenas as duas tools de leitura necessárias e encaminhou as chamadas ao servidor MCP.

O agente escolheu, nesta ordem:
- `listar_filiais({})`, para descobrir filiais e seus serviços;
- `listar_servicos(unidade_id=1000)`, para confirmar o serviço da filial escolhida.

O modelo respondeu **Unidade Centro — Corte Masculino, R$ 45,00**. Conferimos os dados na API pública: filial ID `1000`, serviço ID `1000`, preço `45.0`. Nenhuma reserva foi criada.

---

Na primeira verificação da integração por subprocesso, `listar_filiais` retornou `ConnectError`. Após configurar explicitamente a URL da API para o processo, as consultas funcionaram. **No ensaio com Ollama, o agente não errou na escolha das tools nem nos dados finais.** Ele também não tentou chamar `criar_agendamento`, pois a tarefa solicitava apenas leitura.

A perna da tríade de segurança que exige mais cuidado é a **integridade**: `criar_agendamento` pode alterar a agenda real. A escrita exige sessão autorizada pela AP1, token CSRF, chave de idempotência e aprovação no cliente MCP. Como não havia sessão autenticada de teste, verificamos essa tool com uma API simulada, sem criar atendimento real. Também não foi possível observar a tela de aprovação do Claude Code neste ambiente.

---

Os **cinco testes automatizados** passaram. Além disso, o comando de `aula06/.mcp.json` iniciou o servidor por `stdio`, anunciou as quatro tools e realizou uma leitura pública; o agente Ollama usou o MCP e respondeu com dados conferidos na aplicação.

O exercício pode ser repetido com `uv run --project aula06 python aula06/consultar_com_ollama.py --api-url https://estilomarcado.samuelsantos.qzz.io`. Para experimentar a escrita, `aula06/agendar_com_mcp.py` solicita a sessão localmente, consulta os horários pelo MCP e só cria a reserva após confirmação explícita. Testamos a consulta e o cancelamento desse fluxo sem criar uma reserva real. O planejamento permanece em `aula06/PLANO.md`, ignorado pelo Git.
